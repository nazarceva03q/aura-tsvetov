# Бот «Аура цветов» в Max

Node.js, два независимых режима в одном боте (по user_id пишущего):

- **Покупатель** — согласие на обработку персональных данных → вопрос →
  телефон → свободная переписка с Олесей (пересылка сообщений в обе
  стороны), плюс приём заявок с сайта (тот же вебхук/тот же чат Олеси, с
  проверкой повторного клиента). Каталога, заказа и звонка в этом режиме
  нет — для этого на сайте есть форма «Заказать»; бот здесь — канал связи.
- **Олеся (MAX_OWNER_CHAT_ID)** — меню управления магазином: добавить,
  изменить, удалить товар на сайте, посмотреть заявки. Подробности — раздел
  «Управление каталогом из бота» ниже.

Токен бота уже создан и проверен (`GET /me` живым запросом вернул бота
`@id560903131285_bot`, «Аура- магазин цветов»).

**Деплой — на Yandex Cloud Functions** (по вашему выбору). Инструкция ниже —
под функцию `aura-max-bot`, которую вы уже создали. Вариант с обычной
виртуальной машиной тоже поддерживается кодом (см. раздел «Альтернатива:
виртуальная машина» в конце) — но раз функция уже создана, простее
довести до конца её.

## Важно: сертификат Max требует особого внимания

`platform-api2.max.ru` использует TLS-сертификат от российского
государственного удостоверяющего центра (Минцифры, «Russian Trusted Root
CA»). Этого корня нет в обычных доверенных хранилищах — без него запросы
к Max падают с `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`. Это уже решено в коде:
`bot/src/maxApi.js` сам подмешивает сертификат из
`bot/certs/russian-trusted-ca-bundle.pem` к системным корневым — никаких
дополнительных настроек TLS делать не нужно, это уже проверено живым
запросом к API (включая проверку из уже собранного ZIP-архива для Cloud
Functions — см. ниже).

## Важно: Cloud Functions и хранение состояния

У функции нет постоянного диска между вызовами — каждое сообщение в чате
может обработать другой контейнер. Диалог состоит из нескольких сообщений
подряд (согласие → вопрос → телефон → свободная переписка), поэтому боту
нужно где-то помнить, на каком шаге находится каждый собеседник. Для этого
используется **Yandex Object Storage** (S3-совместимое хранилище) —
код это уже умеет (`bot/src/objectStorage.js`, `bot/src/store.js`),
нужно только создать бакет и ключи доступа (шаг 1 ниже).

## Структура

```
bot/
  index.js                  – точка входа для Yandex Cloud Functions
  server.js                 – альтернативная точка входа для VM (Express)
  src/
    config.js                – переменные окружения
    catalog.js                – СТАТИЧЕСКИЙ каталог товаров сайта (id, категория, цена) —
                                 запасной вариант для notify.js, если товар ещё не в
                                 динамическом каталоге (products.js)
    products.js               – ДИНАМИЧЕСКИЙ каталог товаров (catalog.json в публичном
                                 Object Storage) — то, чем управляет бот через admin.js
    admin.js                  – меню и сценарии владелицы: добавить/изменить/удалить
                                 товар, посмотреть заявки
    store.js                  – сессии/клиенты/вопросы/заявки: Object Storage или локальные файлы
    objectStorage.js          – минимальный S3-клиент (без внешних пакетов)
    maxApi.js                 – обёртка над Max Bot API (+ фикс сертификата)
    notify.js                 – сборка и отправка карточки заявки Олесе (заявки с сайта)
    bot.js                    – маршрутизация апдейтов Max: покупатель → сценарий согласия/
                                 вопроса/телефона; Олеся → admin.js
  scripts/
    setup-webhook.js          – регистрация вебхука в Max (запустить 1 раз)
    build-yandex-zip.cjs      – собирает bot/yandex-deploy.zip для загрузки в консоль
                                 (build-yandex-zip.py — то же самое, если под рукой Python)
    migrate-products.js       – разовый перенос существующих 25 товаров сайта в
                                 catalog.json (запустить 1 раз перед первым использованием
                                 «Изменить/Удалить товар» в боте)
  certs/russian-trusted-ca-bundle.pem
  yandex-deploy.zip          – собранный архив (не в git, пересобирается локально)
```

## Шаг 1. Yandex Object Storage — бакет и ключи доступа

1. Консоль Yandex Cloud → **Object Storage** → **Создать бакет**.
   Имя, например, `aura-max-bot-data` (имена бакетов уникальны во всём
   Yandex Cloud, если занято — добавьте что-то своё, например
   `aura-max-bot-data-2013`). Остальные настройки — по умолчанию,
   доступ **закрытый** (не публичный).

2. Консоль → **Identity and Access Management (IAM)** → **Сервисные
   аккаунты** → **Создать сервисный аккаунт**. Имя, например,
   `aura-bot-storage`. Роль — **`storage.editor`** (даёт право читать и
   писать объекты в бакетах).

3. Откройте созданный сервисный аккаунт → вкладка **«Статические ключи
   доступа»** → **Создать новый ключ** → выберите **«Ключ для сервиса
   Object Storage»**. Появятся **Key ID** и **Secret** — скопируйте
   оба сразу, secret больше нигде не показывается.

Эти три значения (имя бакета, Key ID, Secret) понадобятся в шаге 3
(переменные окружения функции).

### Плюс ОДИН ДОПОЛНИТЕЛЬНЫЙ бакет — для каталога товаров

Это отдельный бакет, специально **публичный на чтение** — в нём лежит
catalog.json (список товаров) и фото, загруженные через бота при
добавлении/изменении товара. Сайт читает его напрямую по HTTPS, без
обращения к функции бота. Держать его отдельно от закрытого бакета выше
важно: в закрытом бакете — сессии/вопросы/телефоны (личные данные), в
этом — только то, что и так видно на сайте всем.

1. Консоль Yandex Cloud → **Object Storage** → **Создать бакет**. Имя,
   например, `aura-catalog` (если занято — `aura-catalog-2013`).
2. При создании (или сразу после, во вкладке **«Доступ»** бакета)
   выберите **чтение объектов: «Публичное»** («Read» → «Everyone»/
   «Публичный»). Запись при этом остаётся закрытой — писать сможет только
   ваш сервисный аккаунт по ключам, как обычно.
3. Тот же сервисный аккаунт из шага выше (`aura-bot-storage`, роль
   `storage.editor`) должен иметь доступ и к этому бакету — если роль
   назначена на весь каталог/облако (а не на конкретный бакет), ничего
   дополнительно делать не нужно; если роль привязана к одному бакету —
   назначьте её ещё раз, уже на новый бакет.

Имя этого бакета понадобится в шаге 2 ниже как `YC_PUBLIC_S3_BUCKET`
(ключи доступа — те же Key ID/Secret, что уже получили).

### Плюс CORS на этом бакете — иначе сайт не увидит каталог

Публичного чтения (шаг 2 выше) достаточно, чтобы файл открывался по прямой
ссылке или через curl — но браузер молча блокирует именно JS-запрос
(`fetch()`, которым index.html подгружает `catalog.json`) с другого домена
(сайт — `aura-flower.shop`, бакет — `storage.yandexcloud.net`), если у
бакета отдельно не включён CORS. В консоли Yandex для Object Storage такой
настройки нет — включается запросом к самому S3 API, для этого есть скрипт:

```bash
cd bot
node scripts/configure-cors.js
```

Запускается один раз (с уже заполненными `YC_PUBLIC_S3_BUCKET`/
`YC_S3_ACCESS_KEY`/`YC_S3_SECRET_KEY` в `bot/.env`, как и `migrate-products.js`
в шаге 6 ниже) — дальше можно не повторять, если только не пересоздадите
бакет заново.

## Шаг 2. Настройка самой функции

Вы уже открыли `aura-max-bot` → **Редактор**. Заполните так:

**Код функции:**

| Поле | Значение |
|---|---|
| Среда выполнения | **Node.js 18** (или новее, если есть в списке — переключите с Python) |
| Источник кода | **ZIP-архив** |
| Файл | загрузите `yandex-deploy.zip` — уже собран и отправлен вам отдельным файлом; как пересобрать после правок кода — см. ниже |
| Точка входа | `index.handler` |

**Параметры:**

| Поле | Значение |
|---|---|
| Таймаут | **30** секунд (по умолчанию 3 — слишком мало: категория с товарами шлёт несколько сообщений подряд) |
| Память | 128 МБ — достаточно |
| Сервисный аккаунт | выберите тот, что создали в шаге 1 (`aura-bot-storage`) |
| Сеть | можно не выбирать |

**Переменные окружения** — добавьте по одной (Ключ / Значение):

```
MAX_BOT_TOKEN        YOUR_MAX_BOT_TOKEN
MAX_OWNER_CHAT_ID     (пусто — заполнить после шага 4)
MAX_ADMIN_CHAT_IDS    (необязательно — см. «Несколько администраторов бота» ниже)
MAX_WEBHOOK_SECRET    придумайте случайную строку без пробелов
SITE_BASE_URL         https://aura-flower.shop
YC_S3_BUCKET          aura-max-bot-data   (имя бакета из шага 1)
YC_S3_ACCESS_KEY      Key ID из шага 1
YC_S3_SECRET_KEY      Secret из шага 1
YC_PUBLIC_S3_BUCKET   aura-catalog        (имя ПУБЛИЧНОГО бакета из шага 1)
```

(Секреты можно вместо этого положить в **«Секреты Yandex Lockbox»** — это
безопаснее, но требует ещё один сервис. Для старта проще и достаточно
обычных переменных окружения — доступ к функции и так закрыт вашим
аккаунтом Yandex Cloud.)

**Логирование** — оставьте включённым, пригодится смотреть, что происходит.

**Асинхронный вызов** — **не включайте**. Боту нужно ответить Max и сайту
сразу (синхронно), а не поставить задачу в очередь.

Нажмите **Сохранить изменения** — запустится сборка новой версии функции.

## Шаг 3. Сделать функцию публичной

Без этого Max и сайт не смогут до неё достучаться (запросы будут
отклоняться с ошибкой авторизации Yandex Cloud, даже не доходя до кода
бота).

Вкладка **Обзор** функции → включите тумблер **«Публичная функция»**.

После этого публичный адрес функции —

```
https://functions.yandexcloud.net/<идентификатор функции>
```

(идентификатор — это `d4e...` / `bba...`-строка, видна там же, на вкладке
«Обзор», рядом с именем функции). Скопируйте этот URL — он понадобится
дальше как для вебхука Max, так и для формы на сайте (это **один и тот же
URL** для обоих — функция сама определяет, откуда пришёл запрос, по форме
тела: апдейты Max всегда содержат `update_type`, заявки с сайта — `phone`).

## Шаг 4. Узнать chat_id Олеси и зарегистрировать вебхук

Регистрировать вебхук удобнее локально (с вашего компьютера, где уже
настроен `bot/.env`), а не из консоли Yandex Cloud:

1. В `bot/.env` (локально) впишите:
   ```
   PUBLIC_SERVER_URL=https://functions.yandexcloud.net/<идентификатор функции>
   MAX_WEBHOOK_SECRET=та же строка, что вписали в переменные окружения функции
   ```
2. Запустите:
   ```bash
   cd bot
   npm run setup-webhook
   ```
   Скрипт проверит токен и скажет «Вебхук зарегистрирован».

3. Попросите Олесю открыть бота в Max по ссылке
   `https://max.ru/id560903131285_bot?start=setup` и нажать «Начать».

4. Откройте в консоли Yandex Cloud вкладку **Логи** функции `aura-max-bot`.
   Там появится строка вида `[bot] bot_started: user_id=123456789`.
   Это и есть `MAX_OWNER_CHAT_ID`.

5. Впишите его в переменные окружения функции (шаг 2) и нажмите
   **Сохранить изменения** ещё раз.

## Шаг 5. Сайт → бот

На сайте (`index.html`) есть константа:

```js
var MAX_LEAD_WEBHOOK_URL = 'https://ЗАМЕНИТЕ-НА-АДРЕС-БОТА.example/webhook/lead';
```

Замените на адрес функции из шага 3 (тот же URL, без `/webhook/lead` —
у функции один URL на всё):

```js
var MAX_LEAD_WEBHOOK_URL = 'https://functions.yandexcloud.net/<идентификатор функции>';
```

Опубликуйте сайт заново — форма «Оставить заявку» начнёт слать заявки боту.

## Шаг 6. Каталог товаров — перенос существующих и связь с сайтом

Товары сайта теперь можно добавлять/менять/удалять из чата Max (см. раздел
«Управление каталогом из бота» ниже) — но чтобы уже существующие 25
товаров тоже стали доступны для редактирования (а не только новые), их
нужно один раз перенести из кода сайта в catalog.json.

1. Заполните `YC_PUBLIC_S3_BUCKET`, `YC_S3_ACCESS_KEY`, `YC_S3_SECRET_KEY`
   в `bot/.env` (те же значения, что и в переменных окружения функции,
   шаг выше).
2. Запустите:
   ```bash
   cd bot
   node scripts/migrate-products.js
   ```
   Скрипт прочитает текущий каталог из `index.html` (var CATALOG) и
   запишет его в `catalog.json` в публичном бакете — точками покажет
   прогресс, в конце выведет прямую ссылку на файл для проверки.
3. Впишите эту ссылку в `business.js` (корень репозитория), поле
   `catalogUrl`:
   ```js
   catalogUrl: 'https://storage.yandexcloud.net/aura-catalog/catalog.json',
   ```
4. Опубликуйте сайт заново (коммит + пуш, как обычно) и откройте его с
   принудительным обновлением кэша (Ctrl+F5). Каталог должен выглядеть
   точно так же, как раньше — просто теперь он подгружается из
   catalog.json, а не только из кода страницы.

**Важно:** запускайте `migrate-products.js` только один раз, до первого
использования «Изменить товар»/«Удалить товар» в боте на этих 25 товарах.
Если запустить его повторно ПОСЛЕ того, как через бота что-то из них уже
удалили или изменили, скрипт вернёт исходные данные из `index.html` поверх
изменений (он не знает про правки, сделанные через бота). Новые товары,
добавленные через бота, при повторном запуске никуда не денутся — скрипт
трогает только те 25 id, что перечислены в `index.html`.

Если `catalogUrl` в `business.js` не заполнен — сайт продолжает работать
как раньше, полностью на встроенном каталоге; ничего не ломается, просто
управление через бота не будет видно на сайте, пока не пройдёте шаги выше.

## Управление каталогом из бота (Олеся)

Когда Олеся открывает бота (или пишет `/start`), вместо приветствия для
покупателя показывается меню:

- **➕ Добавить товар** — по очереди: категория (кнопками) → название →
  цена → состав (или `-`, если описывать не нужно) → одно или несколько
  фото → предпросмотр товара с кнопкой «✏️» на каждую строку и кнопками
  «💾 Сохранить» / «❌ Отмена».
- **✏️ Изменить товар** / **🗑 Удалить товар** — Олеся пишет название
  (необязательно точное — ищет по совпадению), бот присылает подходящие
  товары карточками (текст + фото + кнопка «Этот товар»); дальше —
  редактирование (тот же экран предпросмотра, что и при добавлении) или
  подтверждение удаления (Да/Нет).
- **📋 Заявки** — журнал заказов с сайта и вопросов из чата (кнопка
  «Показать ещё» — более старые).

Товар сохраняется в тот же `catalog.json`, который загружает сайт — правки
появляются на сайте сразу после сохранения (следующее открытие/обновление
страницы), без коммита в GitHub и без участия разработчика.

**Про «бургер-меню»:** в Max нет отдельного, всегда закреплённого элемента
интерфейса для меню (в отличие от Telegram) — это ограничение платформы, а
не этого бота. Ближайший рабочий аналог — команда `/start` и кнопка
«⬅️ В меню», которая добавлена почти к каждому сообщению на каждом шаге:
вместе они дают тот же результат («меню всегда под рукой»), просто в виде
обычной кнопки в последнем сообщении бота, а не отдельного элемента
экрана.

**Про фото:** формат вложений с фото (и то, как Max присылает фото,
отправленное владелицей в чат, и то, можно ли отправить фото по прямой
ссылке, а не заранее загруженным файлом) не был подтверждён живым запросом
на момент написания кода — см. предупреждения в `bot/src/admin.js` и
`bot/src/maxApi.js`. Код разобран защитно (при неудаче показывает то же
сообщение без фото, сценарий не подвисает) и логирует сырой апдейт, если
формат не распознан. После первого реального теста откройте вкладку
«Логи» функции в консоли — если что-то не совпало, правьте только
`extractPhotoAttachments()` в `bot/src/admin.js`.

**Чего это НЕ делает:** отдельные SEO-страницы `catalog/bukety/`,
`catalog/kompozitsii/`, `catalog/poshtuchno/` (генерируются заранее
скриптом `scripts/build-catalog.cjs` и лежат в самом репозитории) не
обновляются автоматически при изменениях через бота — они собираются из
`index.html` во время публикации сайта. Обычные посетители их не видят
(интерактивный каталог на главной странице — из catalog.json, как описано
выше); эти страницы существуют только для поисковых систем и обновятся
при следующей обычной публикации сайта, если кто-то заново запустит
`npm run build` и закоммитит результат.

### Несколько администраторов бота

По умолчанию меню управления магазином видит только `MAX_OWNER_CHAT_ID`
(Олеся). Чтобы дать доступ ещё кому-то (например, разработчику — проверить,
что всё работает), не отбирая доступ у Олеси:

1. Этот человек должен один раз написать боту что угодно (или нажать
   «Начать») — как и в шаге 4 выше для Олеси, это нужно только для того,
   чтобы его user_id попал в логи (сам бот при этом покажет ему обычный
   экран покупателя с запросом согласия — это нормально, дальше можно не
   продолжать, достаточно одного любого сообщения).
2. Console → **Cloud Functions** → `aura-max-bot` → вкладка **«Логи»** —
   найдите свежую строку `[bot] update_type=..., user_id=<ваш id>`.
3. Добавьте (или отредактируйте) переменную окружения функции
   `MAX_ADMIN_CHAT_IDS`, значение — этот user_id. Если админов несколько —
   перечислите через запятую без пробелов: `123456,789012`.
4. **`MAX_OWNER_CHAT_ID` трогать не нужно** — он не входит в
   `MAX_ADMIN_CHAT_IDS` и продолжает быть единственным адресом, куда
   приходят заявки/вопросы покупателей; но доступ к меню у него сохраняется
   всегда автоматически, отдельно прописывать его в `MAX_ADMIN_CHAT_IDS`
   не нужно (и не повредит, если всё же впишете).
5. Сохраните изменения в функции — новый администратор пишет боту `/start`
   и сразу видит то же меню, что и Олеся.

Добавленные администраторы могут полноценно управлять каталогом (добавлять/
менять/удалять товары), но заявки и вопросы покупателей им не приходят —
это по-прежнему только `MAX_OWNER_CHAT_ID`.

## Известные ограничения (сознательно, не забыто)

- **Точные названия полей `message_callback` и вложения `contact` не
  на 100% подтверждены документацией** (часть страниц API-справочника не
  открылась при подготовке кода) — разобраны защитно, с логированием
  необработанных апдейтов целиком. Поле `payload` у кнопок callback уже
  подтверждено живым запросом; если что-то ещё поведёт себя не так —
  смотрите вкладку «Логи» функции в консоли, там будет весь апдейт
  целиком, править нужно только `extract*()`-функции в начале
  `bot/src/bot.js`.
- **Object Storage без сигнатуры проверен только на корректность запроса**
  (правильно построенный подписанный запрос), но не живым PUT/GET к
  реальному бакету — бакета пока не существовало на момент подготовки
  кода. Первая же реальная заявка через бота это проверит; если что-то не
  так — в логах функции будет видно `[objectStorage] PUT/GET ... ->
  <код ошибки>`.
- **`bot/src/catalog.js` — отдельный файл**, не читает сайт напрямую (сайт —
  статический HTML без API). Он больше не единственный источник цены для
  `notify.js` — сначала проверяется динамический каталог
  (`bot/src/products.js`, после `migrate-products.js` в нём вообще все
  товары), `catalog.js` остаётся только запасным вариантом на случай, если
  миграция ещё не выполнялась.
- **Формат фото-вложений Max (входящих и исходящих по прямой ссылке) не
  подтверждён живым запросом** — см. раздел «Управление каталогом из бота»
  выше и предупреждения в `bot/src/admin.js`/`bot/src/maxApi.js`.
- **SEO-страницы `catalog/*/`** не обновляются автоматически при
  добавлении/изменении товара через бота — см. «Управление каталогом из
  бота» выше.

## Альтернатива: виртуальная машина (Compute Cloud)

Если решите не оставаться на Cloud Functions — код это тоже поддерживает,
через `bot/server.js` (обычный Express-сервер) вместо `bot/index.js`.
Отличия от инструкции выше:

- Разворачивается как обычный Node.js-процесс на VM (systemd + Nginx +
  Let's Encrypt для HTTPS) — постоянный диск есть всегда, поэтому
  `YC_S3_*` можно не задавать, подойдут обычные локальные файлы
  (`bot/data/*.json`), которые уже встроены как запасной вариант.
- `PUBLIC_SERVER_URL` для `npm run setup-webhook` — это адрес VM **с
  путём**: `https://bot.aura-flower.shop/webhook/max` (а не бывший URL
  функции без пути).
- `MAX_LEAD_WEBHOOK_URL` на сайте — тоже с путём:
  `https://bot.aura-flower.shop/webhook/lead`.

Если понадобится подробная пошаговая инструкция под VM — спросите, распишу
отдельно (создание ВМ, домен, Nginx, systemd) так же подробно, как раздел
про Cloud Functions выше.
# Проверка повторных сообщений, 10 сентября 2026

Каждый новый вопрос в продолжающемся диалоге передаётся с сохранёнными именем и телефоном. Формат прежний: сообщение с контактом, затем вопрос с кнопкой ответа. Повторные доставки определяются по `message.body.mid` или `callback.callback_id`, независимо от времени повторной доставки и текста. Для реальных ID сохраняется отдельная постоянная отметка в `processed_updates/`: атомарный `If-None-Match: *` в Object Storage или создание файла с `wx` локально. Это предотвращает одновременную обработку одного события разными экземплярами функции. При отсутствии ID остаётся прежняя временная проверка.

Сверено с [форматом callback MAX](https://dev.max.ru/docs-api/methods/POST/answers) и [условной записью Yandex Object Storage](https://yandex.cloud/ru/docs/storage/s3/api-ref/object/upload). Отметка ставится перед обработкой: это защита от повторов, а не гарантия доставки при аварии или отказе API после получения события. Сбой хранилища до отметки возвращается как ошибка обработчика, чтобы событие могло быть доставлено повторно. Отметки не содержат текстов, имён и телефонов и не удаляются автоматически.

Проверки используют тестовые транспорт и хранилище, не отправляя сообщения клиентам. Чтобы применить исправления на работающем боте, обновите код облачной функции архивом `yandex-deploy.zip`; переменные окружения сохраните.
