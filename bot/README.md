# Бот «Аура цветов» в Max

Node.js: главное меню бота, ветки «Букеты» / «Цветы поштучно» /
«Цветочные композиции» / «Заказать звонок» / «Задать вопрос», приём заявок
и с бота, и с сайта (единый вебхук), карточка Олесе с проверкой повторного
клиента.

Токен бота уже создан и проверен (`GET /me` живым запросом вернул бота
`@id560903131285_bot`, «Аура- магазин цветов»).

**Деплой — на Yandex Cloud Functions** (по вашему выбору). Инструкция ниже —
под функцию `aura-max-bot`, которую вы уже создали. Вариант с обычной
виртуальной машиной тоже поддерживается кодом (см. раздел «Альтернатива:
виртуальная машина» в конце) — но раз функция уже создана, простее
довести до конца её.

## Важно: сертификат Max требует особого внимания

`platform-api2.max.ru` использует TLS-сертификат от российского
государственного удостоверяющего центра (Минцифры, «Russian Trusted Root
CA»). Этого корня нет в обычных доверенных хранилищах — без него запросы
к Max падают с `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`. Это уже решено в коде:
`bot/src/maxApi.js` сам подмешивает сертификат из
`bot/certs/russian-trusted-ca-bundle.pem` к системным корневым — никаких
дополнительных настроек TLS делать не нужно, это уже проверено живым
запросом к API (включая проверку из уже собранного ZIP-архива для Cloud
Functions — см. ниже).

## Важно: Cloud Functions и хранение состояния

У функции нет постоянного диска между вызовами — каждое сообщение в чате
может обработать другой контейнер. Диалог заказа состоит из нескольких
сообщений подряд (категория → товар → телефон → имя), поэтому боту нужно
где-то помнить, на каком шаге находится каждый собеседник. Для этого
используется **Yandex Object Storage** (S3-совместимое хранилище) —
код это уже умеет (`bot/src/objectStorage.js`, `bot/src/store.js`),
нужно только создать бакет и ключи доступа (шаг 1 ниже).

## Структура

```
bot/
  index.js                  – точка входа для Yandex Cloud Functions
  server.js                 – альтернативная точка входа для VM (Express)
  src/
    config.js                – переменные окружения
    catalog.js                – каталог товаров = каталог сайта (id, категория, цена)
    store.js                  – сессии/клиенты/вопросы: Object Storage или локальные файлы
    objectStorage.js          – минимальный S3-клиент (без внешних пакетов)
    maxApi.js                 – обёртка над Max Bot API (+ фикс сертификата)
    notify.js                 – сборка и отправка карточки заявки Олесе
    bot.js                    – сценарии диалога (меню → заказ, звонок, вопрос)
  scripts/
    setup-webhook.js          – регистрация вебхука в Max (запустить 1 раз)
    build-yandex-zip.ps1      – собирает bot/yandex-deploy.zip для загрузки в консоль
  certs/russian-trusted-ca-bundle.pem
  yandex-deploy.zip          – собранный архив (не в git, пересобирается локально)
```

## Шаг 1. Yandex Object Storage — бакет и ключи доступа

1. Консоль Yandex Cloud → **Object Storage** → **Создать бакет**.
   Имя, например, `aura-max-bot-data` (имена бакетов уникальны во всём
   Yandex Cloud, если занято — добавьте что-то своё, например
   `aura-max-bot-data-2013`). Остальные настройки — по умолчанию,
   доступ **закрытый** (не публичный).

2. Консоль → **Identity and Access Management (IAM)** → **Сервисные
   аккаунты** → **Создать сервисный аккаунт**. Имя, например,
   `aura-bot-storage`. Роль — **`storage.editor`** (даёт право читать и
   писать объекты в бакетах).

3. Откройте созданный сервисный аккаунт → вкладка **«Статические ключи
   доступа»** → **Создать новый ключ** → выберите **«Ключ для сервиса
   Object Storage»**. Появятся **Key ID** и **Secret** — скопируйте
   оба сразу, secret больше нигде не показывается.

Эти три значения (имя бакета, Key ID, Secret) понадобятся в шаге 3
(переменные окружения функции).

## Шаг 2. Настройка самой функции

Вы уже открыли `aura-max-bot` → **Редактор**. Заполните так:

**Код функции:**

| Поле | Значение |
|---|---|
| Среда выполнения | **Node.js 18** (или новее, если есть в списке — переключите с Python) |
| Источник кода | **ZIP-архив** |
| Файл | загрузите `yandex-deploy.zip` — уже собран и отправлен вам отдельным файлом; как пересобрать после правок кода — см. ниже |
| Точка входа | `index.handler` |

**Параметры:**

| Поле | Значение |
|---|---|
| Таймаут | **30** секунд (по умолчанию 3 — слишком мало: категория с товарами шлёт несколько сообщений подряд) |
| Память | 128 МБ — достаточно |
| Сервисный аккаунт | выберите тот, что создали в шаге 1 (`aura-bot-storage`) |
| Сеть | можно не выбирать |

**Переменные окружения** — добавьте по одной (Ключ / Значение):

```
MAX_BOT_TOKEN        f9LHodD0cOJzJYgI4HEDAEf-zn3AjYkpnMDGJpzc0rLQNi4w8nEuT2JRPcEnKeBFOtHoY2t2ffkpc5TdMsCF
MAX_OWNER_CHAT_ID     (пусто — заполнить после шага 4)
MAX_WEBHOOK_SECRET    придумайте случайную строку без пробелов
SITE_BASE_URL         https://aura-flower.shop
YC_S3_BUCKET          aura-max-bot-data   (имя бакета из шага 1)
YC_S3_ACCESS_KEY      Key ID из шага 1
YC_S3_SECRET_KEY      Secret из шага 1
```

(Секреты можно вместо этого положить в **«Секреты Yandex Lockbox»** — это
безопаснее, но требует ещё один сервис. Для старта проще и достаточно
обычных переменных окружения — доступ к функции и так закрыт вашим
аккаунтом Yandex Cloud.)

**Логирование** — оставьте включённым, пригодится смотреть, что происходит.

**Асинхронный вызов** — **не включайте**. Боту нужно ответить Max и сайту
сразу (синхронно), а не поставить задачу в очередь.

Нажмите **Сохранить изменения** — запустится сборка новой версии функции.

## Шаг 3. Сделать функцию публичной

Без этого Max и сайт не смогут до неё достучаться (запросы будут
отклоняться с ошибкой авторизации Yandex Cloud, даже не доходя до кода
бота).

Вкладка **Обзор** функции → включите тумблер **«Публичная функция»**.

После этого публичный адрес функции —

```
https://functions.yandexcloud.net/<идентификатор функции>
```

(идентификатор — это `d4e...` / `bba...`-строка, видна там же, на вкладке
«Обзор», рядом с именем функции). Скопируйте этот URL — он понадобится
дальше как для вебхука Max, так и для формы на сайте (это **один и тот же
URL** для обоих — функция сама определяет, откуда пришёл запрос, по форме
тела: апдейты Max всегда содержат `update_type`, заявки с сайта — `phone`).

## Шаг 4. Узнать chat_id Олеси и зарегистрировать вебхук

Регистрировать вебхук удобнее локально (с вашего компьютера, где уже
настроен `bot/.env`), а не из консоли Yandex Cloud:

1. В `bot/.env` (локально) впишите:
   ```
   PUBLIC_SERVER_URL=https://functions.yandexcloud.net/<идентификатор функции>
   MAX_WEBHOOK_SECRET=та же строка, что вписали в переменные окружения функции
   ```
2. Запустите:
   ```bash
   cd bot
   npm run setup-webhook
   ```
   Скрипт проверит токен и скажет «Вебхук зарегистрирован».

3. Попросите Олесю открыть бота в Max по ссылке
   `https://max.ru/id560903131285_bot?start=setup` и нажать «Начать».

4. Откройте в консоли Yandex Cloud вкладку **Логи** функции `aura-max-bot`.
   Там появится строка вида `[bot] bot_started: user_id=123456789`.
   Это и есть `MAX_OWNER_CHAT_ID`.

5. Впишите его в переменные окружения функции (шаг 2) и нажмите
   **Сохранить изменения** ещё раз.

## Шаг 5. Сайт → бот

На сайте (`index.html`) есть константа:

```js
var MAX_LEAD_WEBHOOK_URL = 'https://ЗАМЕНИТЕ-НА-АДРЕС-БОТА.example/webhook/lead';
```

Замените на адрес функции из шага 3 (тот же URL, без `/webhook/lead` —
у функции один URL на всё):

```js
var MAX_LEAD_WEBHOOK_URL = 'https://functions.yandexcloud.net/<идентификатор функции>';
```

Опубликуйте сайт заново — форма «Оставить заявку» начнёт слать заявки боту.

## Если меняете код бота

После правок в `index.js` или `src/*.js` пересоберите архив и загрузите
его заново в консоли (Редактор → Источник кода → ZIP-архив → загрузить
новый файл → Сохранить изменения):

```powershell
cd bot
powershell -ExecutionPolicy Bypass -File scripts\build-yandex-zip.ps1
```

## Проверка после деплоя

- [ ] Функция публичная (шаг 3), в переменных окружения задан `YC_S3_BUCKET`
      и остальные `YC_S3_*`
- [ ] Диплинк `https://max.ru/id560903131285_bot?start=test` открывает бота
      и сразу приходит приветствие с меню
- [ ] Кнопки категорий показывают товары с ценами и кнопкой «Хочу такой»
- [ ] «Хочу такой» → просит контакт/телефон → просит/подтверждает имя →
      приходит «Спасибо, …» и Олесе приходит карточка заявки
- [ ] «Заказать звонок» → просит телефон → приходит «Спасибо! Скоро
      перезвоним», Олесе приходит карточка без поля «Имя»
- [ ] «Задать вопрос» → текст вопроса уходит Олесе с кнопкой «Ответить» →
      после ответа Олеси автору вопроса приходит её ответ
- [ ] Повторная заявка с тем же телефоном добавляет в карточку пометку
      «Повторный заказ» (проверяет, что Object Storage реально работает —
      без него это не сохранится между вызовами)
- [ ] На сайте кнопка «Оставить заявку» реально уходит в тот же чат
      (после того как в `index.html` прописан реальный `MAX_LEAD_WEBHOOK_URL`)

## Локальный запуск / тестирование (перед деплоем)

```bash
cd bot
npm install
cp .env.example .env   # заполнить MAX_BOT_TOKEN (уже есть) и остальное
npm start               # поднимает server.js на localhost:3000
```

Без `YC_S3_*` в `.env` бот локально использует обычные файлы
(`bot/data/*.json`) — Object Storage для локальной разработки не нужен.

## Что уже проверено живыми запросами к Max Bot API

- `GET /me` — токен рабочий, бот `@id560903131285_bot`
- `POST /messages` с кнопками — формат тела запроса подтверждён
  (важно: у кнопок поле называется **`payload`**, а не `callback_data`,
  как было в изначальной сводке по документации — это выяснилось именно
  через живой запрос и уже исправлено в коде)
- Весь цикл диалога (меню → категория → заказ → звонок → вопрос → ответ)
  прогнан программно через `bot.handleUpdate()` — все шаги, сессии и
  карточки уведомлений собираются верно
- Собранный `yandex-deploy.zip` распакован и проверен отдельно от
  основной папки — `index.js` корректно находит `src/*.js` и
  `certs/russian-trusted-ca-bundle.pem`, TLS к Max API работает

## Известные ограничения (сознательно, не забыто)

- **Фото в карточках товаров бот пока не шлёт.** На сайте фото — это
  data-URI прямо в HTML, отдельных публичных ссылок на картинки нет.
  Карточки уже готовы принять `attachments` типа `image`, как только
  появится хостинг изображений — правка на пару строк в `bot/src/bot.js`,
  функция `sendCategory`.
- **Точные названия полей `message_callback` и вложения `contact` не
  на 100% подтверждены документацией** (часть страниц API-справочника не
  открылась при подготовке кода) — разобраны защитно, с логированием
  необработанных апдейтов целиком. Поле `payload` у кнопок callback уже
  подтверждено живым запросом; если что-то ещё поведёт себя не так —
  смотрите вкладку «Логи» функции в консоли, там будет весь апдейт
  целиком, править нужно только `extract*()`-функции в начале
  `bot/src/bot.js`.
- **Object Storage без сигнатуры проверен только на корректность запроса**
  (правильно построенный подписанный запрос), но не живым PUT/GET к
  реальному бакету — бакета пока не существовало на момент подготовки
  кода. Первая же реальная заявка через бота это проверит; если что-то не
  так — в логах функции будет видно `[objectStorage] PUT/GET ... ->
  <код ошибки>`.
- **Каталог бота — отдельный файл** (`bot/src/catalog.js`), не читает
  сайт напрямую (сайт — статический HTML без API). Если меняете товары
  на сайте, продублируйте изменения там же.

## Альтернатива: виртуальная машина (Compute Cloud)

Если решите не оставаться на Cloud Functions — код это тоже поддерживает,
через `bot/server.js` (обычный Express-сервер) вместо `bot/index.js`.
Отличия от инструкции выше:

- Разворачивается как обычный Node.js-процесс на VM (systemd + Nginx +
  Let's Encrypt для HTTPS) — постоянный диск есть всегда, поэтому
  `YC_S3_*` можно не задавать, подойдут обычные локальные файлы
  (`bot/data/*.json`), которые уже встроены как запасной вариант.
- `PUBLIC_SERVER_URL` для `npm run setup-webhook` — это адрес VM **с
  путём**: `https://bot.aura-flower.shop/webhook/max` (а не бывший URL
  функции без пути).
- `MAX_LEAD_WEBHOOK_URL` на сайте — тоже с путём:
  `https://bot.aura-flower.shop/webhook/lead`.

Если понадобится подробная пошаговая инструкция под VM — спросите, распишу
отдельно (создание ВМ, домен, Nginx, systemd) так же подробно, как раздел
про Cloud Functions выше.
